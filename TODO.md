Normalize levels according to the codec instead of applying the H.264 convention to HEVC; handle unknown/reserved values safely. - [ ] **Make scoring black-bar-aware and compare real active-image quality** — crop detection is already displayed, but resolution and BPP scoring still reward encoded black pixels. In the verified `Ирония судьбы` pair, the `1920x1080` BDRemux contained only about `1490x1078` of active image while the cropped BDRip was `1492x1080`; bestcut nevertheless awarded the pillarboxed file `7.5` resolution points versus `5.8` and recommended it `45.8` to `42.9`, while side-by-side viewing showed the BDRip looked better. Derive effective resolution and BPP from a stable crop measured at multiple timestamps, never count letterbox/pillarbox pixels as useful resolution, and compare aligned active-image samples for detail/sharpness, compression artifacts and noise with an explicit confidence level. Guard against false crops on dark scenes and intentional mattes. Acceptance: this pair no longer gains points merely for black bars and either ranks the visually stronger BDRip above the BDRemux or reports the quality result as uncertain and requires visual review; add regression fixtures for pillarbox, letterbox, crop-free and dark-scene cases _(added: 2026-08-06)_

- [ ] **Compare synchronized video sequences before classifying duplicates or recommending deletion** — matching or normalized titles may be used only to discover comparison candidates and must never classify files as video duplicates. Metadata, duration, frame count and compressed-stream hashes are also insufficient on their own to distinguish an exact duplicate, a remux, a re-encode and a genuinely different cut. Before any duplicate label or deletion recommendation, obligatorily align timelines and frame sequences despite start offsets, VFR/CFR differences and container timestamps; compare representative checkpoints plus every detected divergence using decoded-frame hashes, SSIM, PSNR/XPSNR, active-image luma/chroma statistics, edge/detail and frame-difference evidence. Detect duplicated, dropped, reordered and replaced frames, edits, alternate masters and localized processing changes, and report whether the files are byte-identical, media-payload-identical, decoded-content-equivalent, a same-cut re-encode, or materially different. Never collapse a same-cut re-encode into an exact duplicate without showing confidence and evidence. Acceptance: two unrelated videos with the same normalized title are never reported as duplicates; the Running Man 714 pair is reported as the same 166,872-frame cut with effectively identical audio but a non-identical video encode (`SSIM 0.994–0.998`, sampled `PSNR 47–55 dB`) and timestamp defects in the organized file; fixtures cover same-name different content, remux-only differences, transparent and visible re-encodes, stable color/contrast changes, offsets, VFR, missing/extra frames, alternate cuts and localized corruption _(added: 2026-08-07)_

- [ ] **Determine actual FPS from timestamps and frame count instead of trusting `r_frame_rate`** — use decoded/packet timestamps, `avg_frame_rate`, `nb_frames / duration` and cadence analysis to derive the effective playback FPS, while retaining the container's nominal rate as separate diagnostic metadata. - [ ] **Detect different masters and color grading before recommending deletion** — files with the same title and duration can use materially different masters or processing. Acceptance: this pair is flagged for color review with the missing x264 tags shown; tests cover color cast, gamma/contrast change, missing or conflicting range/matrix tags, identical grade with different codecs, and naturally different scene lighting _(added: 2026-08-06)_
